## D46 — Bounded read time and concurrency with a fixed error envelope (U21, R55)
2026-10-12. ThreadingHTTPServer starts one thread per connection with no read timeout, so a client that sends a Content-Length and then nothing holds a thread indefinitely; this was a hypothesis from the sources, confirmed on an isolated server during this increment. Chosen: a 10-second socket timeout on each handler, a bounded semaphore of concurrent handlers (8) that refuses with 503 SERVER_BUSY instead of queueing, 408 REQUEST_TIMEOUT for an incomplete body, 400 for deeply nested JSON, 500 INTERNAL_ERROR without a message for any unexpected exception, and a server `handle_error` that prints no exception text. These are process-level limits, not protection against a hostile local process or a network exposure, which the server does not support.

## D50 — The sandbox confines the filesystem with a minimal root, and every control is fail-closed (U21 review, R58e)
2026-10-12. Codex showed that run_isolated.sh mounted the target read-only only under an alias while the original path, the toolchain, the home directory and the host temporary directory stayed reachable with inherited permissions, that the memory limit was optional, and that the probes could pass on empty or malformed output. Chosen: inside the private mount namespace the script builds a new root on the size-limited tmpfs (toolchain directories bind-mounted read-only, the disposable copy and the scratch writable, a private /proc and a minimal /dev), switches to it with pivot_root and unmounts the old root, so that /home, /root, the host /tmp, the original target path and an external dummy file are not reachable; the cgroup memory limit is mandatory; the process limit probe must print two counts with refusals above zero; CPU, file-size and time limits wrap the copy and the probes as well as the payload; any control that is not demonstrated aborts before the payload. The eleven runs made under the previous runner are kept in the report as reported and superseded, not as verified. The script still needs cgroups and user namespaces; where they are missing, the run is recorded as not executed.

## D51 — Connections are capped before a thread exists, and delivery has a deadline (U21 review, R55a)
2026-10-12. Codex showed that the semaphore was acquired inside the handler, after ThreadingHTTPServer had created the thread and read the request line and headers, so connections that never sent headers were not counted, and that the inactivity timeout did not bound a trickle. Chosen: LabServer.process_request acquires the slot before creating the thread and answers 503 on the socket when none is free; the slot is released when the thread ends, on every route; the handler wraps its input stream with a deadline (REQUEST_DEADLINE) that shortens the socket timeout as time runs out, so the request line, the headers and the body together cannot take longer than the deadline whatever the pace of the bytes. The listen backlog stays 16 and is documented as a queue, not a cap.

## D54 — A synthetic /etc and no writable host path inside the sandbox (U21 second review, R58e)
2026-10-12. ## D55 — The deadline is enforced inside every read (U21 second review, R55a)
2026-10-12. Stage 1 (host identity, private mount namespace, outside the PID namespace and invisible to the payload) mounts the tmpfs, starts stage 2 and, only after the PID namespace ended and the cgroup holds no other process, promotes the allowlisted names with scripts/sandbox/promote.py (plain relative names, O_NOFOLLOW and O_NONBLOCK opens, regular file with one link, per-file and cumulative limits, exclusive creation, identity and size rechecked; every name validated before anything is written). Stage 2 (supervisor) receives its script as an argument, holds no host descriptor, is made non-dumpable before the shell starts, and verifies with a probe that no visible process holds a descriptor outside the root. Stage 3 (payload) runs in a nested user and mount namespace, where the kernel locks the read-only, nosuid and nodev flags, with no_new_privs set and dumpable restored for itself; the script verifies from an identical nested namespace that the remount, the supervisor's descriptors and its memory are refused before the payload. Rejected: a second host uid for the payload (not needed once the owner of the export is outside the namespace, and not portable); a writable host bind for the results (rejected in D54). ## D56 — Guards walk typed values, never serialize-only (U21 second review, R54g)
2026-10-12. Codex showed that a quoted credential assignment without digits escaped every guard once the value was serialized to JSON (the escaped quote breaks the pattern and the unquoted branch requires a digit), so an agent definition with such a prompt could be exported from the static build, saved by the store or returned by a model. Chosen: src/lab/sensitive.py and web/sensitive-rules.js expose a walk over strings inside objects and arrays that applies the patterns to each raw value and to the serialized whole; the agent executor, the store, the output validator and both interface guards use it; the dummies include quoted assignments without digits with double and single quotes; the browser check exercises the real export form on the static and the local builds.
