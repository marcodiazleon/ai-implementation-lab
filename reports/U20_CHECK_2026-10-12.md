## Review findings closed without a browser (C262–C268)

- C262 (R49f, D43): on a synthetic repository, a modified tracked file or an untracked file under a served directory makes review, acceptance and deployment false with the files named, while the commit's containment in main stays true with a note; a second commit with the same tree is covered; without Git the states are null. Nothing is staged or committed to compute this.
- C264–C266 (R51d, D44): an empty, malformed or missing code list is rejected; a requirement whose tests call code (derived from the test functions, their fixtures and helpers, not from the classification) cannot be classified document, and such a case cannot be classified structure, without an override that the validator prints and the matrix lists. The committed classification has no override.
- C267 (R53c): the test helper reads every child as UTF-8 with replacement and starts Python children in UTF-8 mode; the fail-closed test passes under a cp1252 parent, under PYTHONUTF8=1 and under `python -X utf8` without variables.
- C268 (R52): the README and the Spanish guide say that `?` replaces what the console cannot encode (cp1252 does print Spanish accents) and list the four regenerated files to restore, without a tree-wide reset.
